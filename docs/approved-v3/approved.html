写一条→螃蟹键盘→完成保存→按日回看

留下一句话，
也留下一天。

一本安静的腕上笔记本。短便签与长记录共用一份内容：当下随手写，以后按日期找。不先填标题，也不要求完成一篇日记。

SCENES / 浏览方案

READING / 长文体验

阅读页不常驻大按钮，正文按实际屏幕轮廓逐行排版；只翻完整屏，不把汉字拦腰裁断。

手机在表内上下滑动，电脑滚轮翻屏。表内右上三个点进入更多操作：字号、从头阅读、编辑记录与记录操作保持原样。进度按正文位置记录；切换尺寸和字号仍从附近继续。初始记录均为演示文案。

INPUT / 效果稿辅助输入

这块输入区只在网页外侧，不是手表控件。编辑已有记录先显示正文；点正文定位光标并展开键盘，顶栏下箭头可收起。正文上下滑动翻屏；键位区域横滑找键。键盘按键可点击；横滑可找右侧键位；长按或上滑取上层字符。候选演示使用原仓 flash 词库的有限摘录，不等于完整输入引擎。

DESIGN / 三条原则

① 内容比装饰更重要：暖白正文、黑底、少量纸金。
② 写的时候只管写：默认无标题，退出可留草稿。
③ 熟悉的输入不重做：保留螃蟹键盘键位与操作习惯。

一份记录，两种观看

“随记”解决现在想写什么；“回看”解决那天发生了什么。便签不必搬去另一个模块，日记也不必每天只写一篇。列表标题来自正文首行。

腕上，而不是缩小的手机

首页和回看保留底部导航，但减少段间空隙，列表吃满可用高度。阅读页把操作收进顶栏，正文按每一行所在位置计算安全宽度：圆屏中部展开、上下收窄，方屏在圆角之外充分铺开。尺寸切换仍只是效果稿检查。

离线优先，记录归自己

首版方案不要求账号、网络或手机伴侣，不加入 AI 分析、连续打卡和情绪分数。真实应用的数据可靠性、堆内存与文件接口，必须等开始开发后在真机验收。

产品方向收益代价 / 选择理由
统一记录 · 推荐一键开写，长短内容共存，时间回看与置顶便签同源。最贴合手表碎片输入；不增加类别切换，后续也能扩展。
便签优先进入快、信息少，适合临时事项。以长期记录为目标时，日期与上下文容易被压弱。
日记优先日期主线明确，适合每天回顾。每日一篇、模板和打卡会增加填写负担，不适合作为默认。
边界说明：这是独立浏览器视觉 / 交互效果稿，不是 HarmonyOS 手表模拟器，也未建立、构建或安装手表 App。所有初始记录均为演示文案；你在网页里保存的内容仅留在此浏览器本地，不会上传或写入手表。网页缓存可丢失，不应作为真实日记存储。
