# IO_BUSY 初始化时序修复范围

基底：3d1411153bf132fa26a853093c4af70dc2057984。目标真机 FIT3，截图读取失败 IO_BUSY。

已确认：store.init 在无 current 且 busy=true 时立即返回 IO_BUSY；首页激活把该回调视为读取失败并跳页。真实隔离磁盘＋自研模拟器在第一次初始化回调延迟、实际执行 hide/show 后复现同款页面。没有注入文件失败，没有证明 FIT3 首次回调迟到的具体原因。

公共验收接口沿用现有边界：store 的 init/save/read/list 回调；真实页面 onInit/onHide/onShow 与保存/导航，不断言私有变量。

要求：
1. 多个初始化调用只运行一条文件 I/O 链，等待同一次成功或实际失败；正常延迟不返回 IO_BUSY。
2. 初始化订阅数有小而明确的上限；超限显式报错，不积累无限回调或启动新的写入链。
3. 初始化实际失败仍原样显示，不把文件损坏、权限等错误当成空仓库；失败后可显式重试。
4. 所有订阅最多完成一次；一个订阅异常不阻断其他订阅，异常记录固定标记，不输出正文。
5. 页面失活的回调无路由副作用；最新激活收到完成结果。销毁仓库后不报告成功、不继续发起新 I/O。
6. 原有写互斥、journal 回滚、校验、文件 URI/格式、V3 HML/CSS/布局保持不变；不超时强制释放写锁，不删任何真机记录。
7. 版本 0.2.2/code4，同签名身份覆盖升级；构建、签后载荷、保存读回需真实验证。模拟器成功仍不是 FIT3 最终修复证明。
